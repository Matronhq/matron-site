YOUR FIRST MATRON

A computer that works.
A place to talk to it.

Rent a small computer that stays on. Run one guided setup. Open Matron and give your first agent a job.

An agent is an AI that can use tools and carry out work. A box is a computer it runs on. You can start with one.

This guide sets up text chat and file sharing. Email and other service integrations are not included.

Before you buy: you need a computer for the initial setup, an SSH key, and a Claude Code or Codex account with access to its command-line app. The server and AI usage are separate bills. Matron is open source; it does not include either subscription.

START HERE

Get a VPS

A VPS is a rented computer on the internet. Order a fresh Ubuntu 24.04 server, x86-64, with at least 2 CPUs, 4 GB RAM, 40 GB disk and a stable public IPv4 address. Choose a location near you. Larger jobs or several agents may need more memory.

Compare these budget options. Start with a short commitment while trying Matron; the lowest advertised monthly equivalent can require a longer contract.

Create an SSH key and connect

An SSH key lets your computer sign into the server. On your own computer, open Terminal on macOS/Linux or PowerShell on Windows and run:

ssh-keygen -t ed25519

Accept the suggested location only if it does not replace an existing key. Choose a passphrase. Upload the public key to the VPS dashboard when it asks for an SSH key. Keep the private key on your computer.

To display the public key on macOS/Linux:

cat ~/.ssh/id_ed25519.pub

On Windows PowerShell:

Get-Content $HOME\.ssh\id_ed25519.pub

Use the SSH connection command in your provider's dashboard, or its browser console. It supplies the initial username and IP address. If it uses an initial password, enter that only in the server login prompt. Keep this connection open until setup finishes.

In the provider's firewall, allow incoming TCP ports 22, 80, 443 and 8444. Port 80 is needed again for automatic certificate renewal. You do not need a domain name for your first chat.

You should now have: a server terminal ready for the next command, its public IPv4 address, and your SSH public key.
2

ONE GUIDED SETUP

Run this script

Paste this into the new VPS's terminal. The installer configures the server, including its SSH login and firewall, so use a fresh VPS for this path.

curl -fsSL https://raw.githubusercontent.com/matronhq/dev-boxer/main/install.sh | sudo bash

Read the installer · Source and advanced installation

  1. Choose 1 — Set up my first Matron.
  2. Choose a sign-in name and your AI provider: claude or codex.
  3. Enter the VPS's public IPv4 address, accept the certificate terms, and confirm your SSH public key.
  4. Let setup install the parts. When prompted, open the AI provider's sign-in link on your own computer. Follow its instructions, then return to the terminal. For Codex, you may need to enable device-code sign-in in your account's security settings.
  5. Open the Open Matron address it prints. Sign in with the name and generated password shown in your terminal. Save the password in your password manager. A short-lived QR also lets you sign in from the Matron phone app.

Sign-in help: Claude Code · Codex.

Behind the scenes, setup installs the browser app, your conversation store (the journal), the connection to the AI (the bridge), and a file viewer. It sets up trusted HTTPS, automatic startup, and one AI provider. This starter setup uses text chat; voice transcription and development extras are optional advanced configuration.

This is your own computer, and the agent account can administer it with sudo. Add only accounts and data you intend it to use.

Next time you connect by SSH: use ssh dev@YOUR_VPS_IP. Setup keeps port 22, installs your key, and disables root and password SSH login. Try this in a second terminal before closing the first.
3

CHECK IT WORKS

Start your first chat

In Matron, click the pencil button (New session), then choose your box if asked. Leave Folder path blank to use the prepared work folder, then click Start.

Give your agent a small job

Send:

Say hello, then put a notice in For you saying my first chat works.

Check that you get a reply and that the notice appears in For you. A running service alone does not prove the chat is ready.

If the agent cannot reply, reconnect to the VPS and run sudo matron login to check your AI sign-in. The recovery commands below help with other setup problems.

You should now have: a working chat and a notice in For you. You can start giving your agent work on this box.
4

OPTIONAL · WHEN YOU NEED MORE ROOM

Want more boxes?

Get another fresh VPS using step 1. Run the same script on it and choose 2 — Add a box to my Matron.

Use your existing sign-in name, choose its AI provider, then enter your existing Matron HTTPS address without /app/. Setup shows a pairing code: sign into your existing Matron and approve this box there.

Sign into the AI provider on the new box when prompted. It appears alongside your first box in Matron. It uses the same journal and has its own revocable connection; there is no need to copy passwords or AI sign-in files between servers.

For a computer you already own, use the separate bridge installation guide.

You should now see: both boxes when starting a chat. Try a short chat on the new one before giving it a job.

If you get stuck

Reconnect with ssh dev@YOUR_VPS_IP. If setup stopped before creating that account, use the provider's original login or browser console.

Setup stopped or the connection dropped
Run the installer command again. It resumes using your saved settings and installed version. If available, sudo matron resume does the same.
Check what needs attention
sudo matron status checks services, the browser and certificate renewal. It gives the next command if something needs fixing.
Sign into the AI again
sudo matron login
Show your password and a fresh phone sign-in QR
sudo matron link — use your private SSH terminal. Do not paste its output into chat.
Pair a revoked box again
sudo matron enroll
Backups, restores and updates

sudo matron backup briefly stops Matron and saves a private archive. Copy it off the VPS to private storage. It contains credentials and conversation data. It excludes your work folders and AI sign-in sessions: back up your work separately and sign into your AI again after recovery.

To restore, first install Matron on the replacement VPS with the same sign-in name and first-box/add-box choice. Copy your archive there, then run sudo matron restore /path/to/backup.tar.gz --replace-state. This replaces its Matron state and reapplies the new server address. Keep the old server stopped when moving a box.

For a deliberate update, make a backup, then run sudo matron update --backup /path/to/backup.tar.gz. Repeating ordinary setup does not update Matron components. Full recovery guide and backup limits.

The HTTPS certificate needs attention

Keep port 80 reachable in both the provider's firewall and the VPS. Check sudo journalctl -u matron-certificate.service, then run sudo systemctl start matron-certificate.service to retry. Never bypass a browser certificate warning. If the public IP changed, update it in /opt/dev-boxer/config.yml and resume setup.

Still stuck? Get support. Share the step name and error, after removing passwords, sign-in codes and tokens.
